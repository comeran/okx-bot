# Strategy spot ledger and allocation readiness — Phase 2b

Continue the authorized spot-first roadmap for personal single-node OKX use. Phase 2a is local commit `7fa0bc1`. This slice supplies an internal durable accounting kernel and a read-only allocation-readiness preview. It does not activate allocations, start strategies, call private providers, or authorize real orders.

## Accounting boundary

Use separate SQLAlchemy tables and Decimal text values in the validated per-account facts database. Do not retrofit the legacy float paper accounting service or add live ownership hooks to Repository. `SpotLedgerStore(engine, scope)` validates the immutable scope header before creating/reading its tables; passing the master DB or a different scope fails closed. Existing paper/backtest behavior is unchanged.

Internal `initialize_strategy` creates a **prepared**, non-executing ledger from an exact quote budget, saved allocation-scope ID and draft revision. It starts with zero base, zero PnL and no inferred external holdings. This is local accounting initialization, not a transfer or proof of exchange funds. No REST endpoint calls initialization or any ledger mutation. One strategy and one canonical spot symbol are exclusive within the account store. Reject self-pairs whose base and quote currency are equal. Exact repeats are idempotent; changed seed parameters conflict. No top-up, reset, withdrawal, implicit reinitialization or symbol change in this slice.

Amounts accept Decimal, decimal strings or integers, never bool/float/NaN/infinity. Bound external inputs to at most 18 integer and 18 fractional digits; use a private precision-80 Decimal context for arithmetic and TEXT persistence, independent of the process Decimal context. Computed cost allocation uses that deterministic precision; the final complete base disposal removes the exact remaining cost basis. No balance may become negative and no reserved amount may exceed its asset balance.

`reserve_order` reserves buy quote `amount * price_cap + fee_buffer`, or sell base `amount + fee_buffer`. Buy orders require a positive maximum execution price. Fee buffer is denominated in the reserved asset. No naked sell, budget overspend or competing order may consume another reservation. Persist immutable order intent, actual filled quantity and unspent fee buffer. Repeating the same order identity with changed intent conflicts, including attempts to revive a terminal order.

`apply_fill` accepts a globally unique within-account trade ID, the owning strategy/order, incremental base quantity, price, nonnegative fee and explicit base/quote fee currency. Duplicate exact payloads have no additional effect; changed payloads or cross-strategy identity reuse conflict. Buy quote fee consumes its quote fee buffer; buy base fee must be strictly less than that fill's gross base quantity so net received base stays positive. Sell base fee consumes its base fee buffer; sell quote fee must not exceed that fill's proceeds. Third-currency fees, rebates, excessive fees, price-cap violations and overfills fail with no writes. These are internal exact inputs; future exchange integration must supply exact quote cost and fee currency rather than reinterpret legacy float snapshots as authoritative fills.

Buy cost basis capitalizes the full quote debit over the net base received. Sell realized quote PnL is net quote proceeds minus the proportional cost of base disposed (including base fee). Remaining reservations use remaining quantity and the **unspent** fee buffer. Unknown submission/cancel outcomes retain reservations. `confirm_terminal` releases remaining reserves only for canceled/rejected/filled status with confirmed cumulative quantity exactly matching accounted fills; filled must equal the full order quantity. A missing order from an open-order list, timeout or cancel acknowledgement is not terminal proof. Every state change and its audit event commit together; any failure rolls back all balances, reservations, fills and events. Terminal duplicate confirmation is idempotent only when its immutable values match.

Read model: prepared strategy snapshot includes strategy/symbol/currency, allocation_scope_id/draft_revision, initial_quote, quote/base balance/reserved/available, cost_basis_quote, realized_pnl_quote, fees by currency, version and `execution_ready:false`. All monetary/quantity values serialize as decimal strings. No fictitious default initial capital. Reservation/fill ledger methods remain internal and unconnected to UnifiedOrderManager until activation/reconciliation prerequisites exist.

## Readiness preview

Add `GET /api/allocations/{strategy}/readiness` with mandatory query preconditions `expected_account_scope_id`, `expected_scope_id` (existing allocation scope), `expected_revision`, `expected_symbol`. Capture configuration once; map the unchanged Phase 1 allocation scope to execution scope from the same key/environment. Hold the existing strategy lifecycle lock while verifying saved draft and symbol. Missing/changed draft/symbol/revision/scope returns 409; unknown strategy remains 404. Use only the bound facts store and master drafts/global kill. No provider requests, financial mutations, ledger initialization or active allocation transition.

Response fields: `execution_context`, `allocation_scope_id`, `draft_revision`, `strategy`, `symbol`, `currency`, `budget` (string), `evaluated_at`, `capacity:{observed_quote_available:string|null, proposed_total:string, comparison:'within_observed'|'exceeds_observed'|'unavailable', trusted:false}`, `ledger` (prepared snapshot or null), `checks:[{code,status:'passed'|'blocked'|'unknown'}]`, `can_activate:false`, `execution_ready:false`.

Sum non-deleted saved drafts in the same allocation scope/quote currency using Decimal(str(stored budget)); this is an indicative proposal comparison, not exact funded accounting. Never compare a quote budget against USD account equity/cash. Duplicate/missing quote-asset fields, malformed/untrusted observations yield unknown capacity; do not fabricate a missing asset as zero. Existing avail_bal may be a provider fallback or normalized value, so even a comparison within the observed number cannot pass authoritative cash capacity. Persisted account updated_at is a provider timestamp, not a received-at/full-sync receipt. Evaluate timestamp age explicitly (30 seconds maximum, at most 5 seconds into the future); label the check provider_timestamp only.

Checks describe available evidence without implying activation: `strategy_stopped`, `account_snapshot`, `provider_timestamp`, `global_kill`, `account_kill`, `observed_open_orders`, `quote_capacity`, `ledger_state`, `identity_verified`, `account_mode`, `instrument_metadata`, `sync_completeness`, `reconciliation`, `activation_implemented`. Existing active exchange orders/unknown outcomes block; an empty persisted order list is unknown completeness, not proof of no exchange orders. Quote capacity, identity, account mode, instrument metadata, full sync/reconciliation remain unknown unless this slice has actual trustworthy evidence (it does not add such evidence). `activation_implemented` is blocked. A draft without a ledger displays uninitialized; matching prepared ledgers remain non-executing, mismatching seed/symbol/revision blocks. No snapshot bootstrap or legacy live import.

Readiness is diagnostic across master/facts files, not an atomic activation certificate. Any future activation must revalidate all trusted evidence and capacity in its write transaction. This avoids implying a cross-database financial transaction or a fresh private-sync completeness claim.

## Client behavior

Extend the allocation panel with a read-only readiness component for the saved draft. Display saved budget, indicative total proposals/current quote observation, ledger status/balances/reservations and translated evidence/blocker labels. Do not add activation/start actions. Unsaved budget edits do not change readiness; explain that it evaluates the saved draft. Errors are distinct from unknown conditions.

Account epoch, strategy, allocation scope, saved revision and symbol fence every readiness response, error and finally callback. Clear the allocation envelope and readiness immediately on account invalidation; reload after authoritative context resolves. A→B→A or delete/recreate cannot revive old readiness. Render monetary strings without converting to Number. Preserve no-credentials draft behavior and local paper lifecycle/performance.

The draft envelope also carries `execution_context`, derived alongside allocation context from one captured configuration. Match this field to the authoritative account-context store before showing an editable envelope; responses never select account identity. Saved strategy-symbol and lifecycle changes invalidate the envelope and preview. Show evaluation time so a cached provider-timestamp check is visibly as of that check, with manual refresh.

## Acceptance

- Exact reserve/fill/terminal arithmetic, base/quote fees, idempotent replays and audit rollback survive reopen and concurrent requests.
- Two strategies cannot share the same spot symbol or trade/order identity; two account stores can reuse identities without mixing data.
- Unknown and partial-fill cancellation paths retain funds until an exact reconciled terminal checkpoint.
- Readiness reads the scoped store, never initializes any ledger or contacts OKX, rejects stale preconditions and cannot grant live ownership.
- Indicative float-derived observations and empty order lists never become authoritative capacity/completeness passes.
- Client pending success/error/finally and visible readiness are invalidated by account/draft changes; no activation control is introduced.
